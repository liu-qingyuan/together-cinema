Prepare the host

These steps use the current main branch and build the application locally. Install Git, Docker Engine or Docker Desktop, and Compose v2 with support for up --wait. Start Docker and confirm you are connected to the intended engine:

docker context show
docker compose version
docker info

For local playback, start with 1 vCPU and 1 GiB RAM (2 GiB recommended). Leave room for the image, films, and both input and output during conversion. The default 2 GiB free-space reserve prevents writes; it is not preallocated storage. The installer does not install Docker or change your firewall.

Start on your own computer

git clone https://github.com/liu-qingyuan/together-cinema.git
cd together-cinema
./install.sh

Prefer not to use Git? Download the main source ZIP, extract it, enter its directory, and run just ./install.sh. The first build downloads dependencies. Older releases may differ.

Check it: open http://127.0.0.1:8080 on the Docker host. You should see the gallery. Enter a new room code of 2–8 letters or digits and look for the room number. This address is local only: don’t send it to a friend.

If it does not open, check docker compose ps and docker compose logs --tail=100 watch. If the port is in use, run ./install.sh --port 8088 and open that port instead.

Invite someone over HTTPS

On a publicly reachable server, point your domain’s DNS at that server. Allow inbound TCP 80 and 443. From the project directory on that server, replace the example hostname with yours:

./install.sh --domain cinema.example.com

Open your domain over HTTPS. The gateway username is cinema; use SITE_PASSWORD from your private .env. WATCH_PASSWORD is an internal secret, not the login password. If certificates are pending, check DNS, ports, and docker compose logs --tail=100 https.

Invite trusted friends only. Room codes do not protect or isolate the library: admitted viewers can watch, upload and delete films site-wide. Don’t expose unprotected port 8080 or share your .env. Send the invitation and gateway credentials privately.

Add discovery or voice if needed

Online video

Library playback, public HTTPS media and discoverable static pages do not require the browser image. For sites that load playable media dynamically, allow more build space and preferably at least 2 GiB RAM on the host. From the same project directory:

./install.sh --network

On a first public installation you can combine --network --domain cinema.example.com. Not every page can be resolved. See direct versus relay before choosing: relay uses server egress for each viewer.

Voice chat

For public voice, serve the site over HTTPS and configure an external TURN service. In private .env set WATCH_TURN_URLS and WATCH_TURN_SECRET to match that service, then rerun the installer. Text chat needs no TURN.

Update without losing the library

Back up the private .env and project data volumes. Wait until the screening ends: rebuilding can interrupt connections. In the original Git checkout, review the changes, then run:

git pull --ff-only
./install.sh
docker compose ps

If you installed from a ZIP, update the source in the original directory instead of running git pull. Keep your .env, Compose project name and named volumes. Run the installer and check an existing film and subtitle track.

./uninstall.sh stops the project but keeps data. Adding --purge-data --yes permanently deletes project volumes, including media and certificates. Do not use it for an update.
